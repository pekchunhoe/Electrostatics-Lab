# Dynamic Equilibrium: gravity and adjustable magnetic balancing

Local implementation and validation, 18 October 2026 (Asia/Kuala_Lumpur). Scope: Uniform Electric Field, Experiment D. This report supersedes the artificial-force description of D in `UNIFORM_FIELD_ADVANCED_VALIDATION.md`.

1. **Files modified.** Updated `src/app.js`, `src/physics.js`, `src/motion-state.js`, `src/motion-ui.js`, `src/motion-render.js`, `src/presets.js`, `src/learning.js`, `src/styles.css` and the numerical-test script in `package.json`. Added `src/lorentz.js`, `tests/magnetic-motion.test.js`, `tests/browser/magnetic-motion.spec.js`, `scripts/benchmark-magnetic.mjs`, `docs/magnetic-performance.json`, this report and screenshots under `docs/screenshots/dynamic-equilibrium/`. Adapted the existing motion and learning tests to D's new physical model. No dependencies or hosting configuration changed. Build output is local, ignored `dist/` content.

2. **External Force removed from D.** D presets delete `externalX` and `externalY`. D has no external-force input, legend entry, arrow, calculation, rebalance operation or hidden balancing vector. Its force engine also ignores any stale external values defensively. The existing external-force controls and behavior remain available to A–C to satisfy preservation requirements. Existing tests that asserted an artificial force in D were replaced with assertions for real magnetic balancing; their coverage was retained and expanded, without skipping tests.

3. **Gravity mode.** Only electric force and weight act: FE = qE, Fg = (0, −mg), a = (FE + Fg)/m. Gravity remains downward for either orientation. Horizontal initialization retains q = 1 nC, m = 1 mg, d = 0.08 m and voltage = 784.8 V, giving upward E = 9810 N/C and zero resultant. Charge, mass, voltage, polarity and separation edits break balance according to the actual force sum. The explicit gravity button identifies its adjustment: voltage = mgd/q. It rejects zero charge, vertical plates or required voltages outside the existing ±2000 V control range, without corrupting parameters.

4. **Magnetic mode.** Only FE and FB act; gravity is neglected even if an obsolete gravity flag remains. B has a nonnegative magnitude in Tesla and a separate direction of −1 or +1. Bz = B × direction. For the instantaneous velocity, FB = (q vy Bz, −q vx Bz), ax = (q/m)(Ex + vy Bz), ay = (q/m)(Ey − vx Bz). Zero speed gives zero FB. Signed charge reverses both electric and magnetic contributions. A zero-charge particle is explicitly identified as a trivial zero-force case, rather than an electric–magnetic balancing demonstration.

5. **Adjustable B.** The magnetic disclosure includes a touch-sized slider, precise numeric input, Tesla unit and live output. Both store the same B. Default B is 0.20 T; supported magnitude is 0–2 T. Slider interaction rounds to 0.01 T; `step=any` lets the slider thumb retain precise values entered numerically. Numeric entry supports scientific notation and arbitrary finite precision within range. Negative, empty, nonfinite and out-of-range values are rejected before state mutation. B = 0 is allowed, removes FB and its arrow, and reports that magnetic balancing is unavailable for nonzero E. A zero field has no canvas symbols; the direction legend retains the selected direction and identifies the zero magnitude.

6. **Direction reversal.** Reverse Magnetic Field changes only the direction sign. Magnitude, instantaneous position and velocity are preserved. Crosses become dots or vice versa, FB reverses for fixed velocity, and the resultant, acceleration and status update. It does not rebalance. Direction changes use the same time-history mechanism as B magnitude changes.

7. **Full-canvas visualization.** Repeated × symbols represent into-page B; • symbols represent out-of-page B. Symbols cover the canvas beyond the plates, with 34 px spacing on narrow canvases and 46 px otherwise. They are drawn before plates, particle, trajectories and force vectors, using theme-aware subdued colors. They are confined to the canvas. The legend states direction and actual B. FE and FB have separate labels; the zero-acceleration annotation sits in the canvas header to avoid intersecting a plate.

8. **Orientation defaults and manual selection.** Horizontal D opens in balanced Gravity. Vertical D opens in Magnetic. Changing D to vertical selects Magnetic automatically and explicitly initializes velocity to E × B/B² while preserving compatible q, m, voltage, gap, length, polarity and B. If the prior B is zero or cannot support a velocity within the balancing control's range, this orientation preset uses 0.20 T and announces that adjustment. Zero charge remains identified separately. A student can then select vertical Gravity and retain it across parameter edits or unrelated main-tab changes. Vertical Gravity shows the perpendicular-force explanation and the correct downward/horizontal resultant. Returning to horizontal selects Gravity while preserving parameters; balancing voltage requires the explicit button. Orientation changes reset playback and time.

9. **Explicit magnetic balancing.** Balance with Magnetic Force reads E and signed B, computes initial vx = Ey/Bz and vy = −Ex/Bz, preserves B, direction, charge, mass and plates, and resets playback and time. It rejects B = 0, zero charge and an unrepresentable or greater-than-1e9 m/s required speed before changing velocity. Manual speed entry changes initial speed along the intended tangent direction and resets time; it does not change B. Signed vx/vy remain editable in precise settings. Initial launch direction is stated next to the controls.

10. **Changing B and live continuity.** A B edit updates force, acceleration, equilibrium status, force arrows and the future trajectory immediately, without changing velocity to restore balance. During playback or a paused unfinished flight, it records a new field epoch at the current simulated time. Earlier epochs reproduce the previous trajectory with their own B; subsequent motion uses the new field. Current position, velocity, elapsed time and playing/paused state remain continuous. Repeated edits at the same instant replace that epoch rather than creating duplicate time segments. After an already completed flight, a field edit explicitly restarts at time zero and says so. Replay clears history and launches with the current controls. Other particle/plate edits retain the existing pause-and-reset interaction policy.

11. **Lorentz motion method.** `lorentz.js` propagates each uniform E/B segment in closed form, with signed angular frequency ω = qBz/m. It expresses the solution through the initial acceleration to avoid cancellation from a large E/B drift at tiny B. Sine/cosine quotients use series through sixth order for |ωt| < 0.001. B = 0 takes the exact constant-electric-acceleration limit. No Euler stepping, fixed artificial FB or rescaling of physical curvature is used. The constant-acceleration engine is retained for Gravity and A–C.

    Event searches normally span at most a quarter gyroperiod. Coordinate turning points are located by splitting velocity at analytical acceleration zeros and bisecting the velocity roots; coordinate boundary roots are then bisected over monotone intervals. Bisection uses 52 iterations. A conservative drift-plus-orbit envelope permits longer exact propagation only when it establishes that no relevant boundary can be reached. This keeps confined high-frequency orbits fast. When E = 0, former electric-region ends are not force discontinuities, so they do not generate redundant transitions. Plate and canvas checks remain active.

12. **Magnetic-only validation.** Supplied reference F uses m = 1e−6 kg, q = 1e−6 C, v = 500 m/s: r = 2500 m at B = 0.20 T and 1250 m at 0.40 T. These large radii remain physically large. Tests independently compare positions, radius, speed, energy and curvature at quarter/half/full periods and after 100 periods. A separate visible reference uses q = 100 nC, m = 0.001 mg, B = 0.20 T and v = 2 m/s, giving r = 0.1 m and |ω| = 20 rad/s. The browser's contained-orbit example uses v = 1 m/s, hence r = 0.05 m, with x0 = 0.12 m, y0 = 0, L = 0.10 m, d = 0.08 m and voltage = 0. Both charge signs and B directions are checked. The maximum supported B/q/m case is also propagated to 3600 s without a spurious spiral or false exit.

13. **Field exit, re-entry and collisions.** Outside the finite electric rectangle E becomes zero while B remains selected throughout the canvas. Position and velocity are continuous across transitions. Re-entry restores E when the trajectory enters the region. Independent small-step RK4 references check a nonzero-E exit/re-entry trajectory; this reference integrates the component equations independently rather than calling the closed-form step. Curved plate contact, including grazing contact, is localized at the conducting surface and stops the absorbing particle. Canvas bounds include the existing 9 CSS-pixel disk radius. Exact outward boundary states and event priority are tested. The particle remains visible during a contained circle; it is not labelled exited.

14. **Timer and playback.** The existing single physical clock, Play/Pause, Step, Replay, Reset and speed multiplier are retained. Field exit is nonterminal. Plate impact, full canvas exit, stationary equilibrium and the labelled time safeguard stop playback and freeze final time/trajectory. A momentary zero velocity with nonzero force does not stop motion. The existing A–C clock remains 0.1 simulated seconds per real second at 1×. Magnetic D uses min(0.1, 0.15 L/initial_speed), so the existing high field/nC/mg scale remains observable without changing SI motion. The selected clock rate is displayed. Step uses min(0.01, 0.1 × that rate), and its button shows the actual step. The timer always reports physical simulated seconds.

15. **Independent numerical tests and tolerances.** `npm test` passes **177 tests, zero failures**. Coverage includes all existing electrostatic, potential, equipotential, learning and A–C regressions, plus magnetic/gravity cases. Supplied references verify E = 9810 N/C; forces ±9.81e−6 N; vertical a = (9.81, −9.81) m/s² for equal normal electric acceleration; and FE = FB = 1e−4 N for E = 100 N/C, B = 0.20 T, v = 500 m/s, q = 1e−6 C. Using independently selected m = 2e−6 kg, B = 0.10/0.40/0 T gives FB = 5e−5/2e−4/0 N and ay = −25/+50/−50 m/s² in the stated opposing-force arrangement.

    Ordinary new references use relative 2e−10 or absolute 2e−12 in SI units. Large-radius 100-period positions/radius allow 2e−7 m; speed allows 2e−8 m/s; kinetic energy allows 2e−11 J. The independent RK4 comparison uses dt = 1 microsecond, 5e−7 m position and 1e−5 m/s velocity tolerance, accounting for its separately sampled discontinuities. Browser force and trajectory references usually allow 1e−9 SI absolute error; terminal collision comparisons use 1e−10 s. Boundary coordinate endpoint detection uses 2e−13 × max(1, |boundary|) m and finite plate-end inclusion allows 2e−12 m.

    Force summation removes only roundoff within four machine epsilons of the largest component contribution. Balanced status uses 32 epsilons relative to the largest active force. Small genuine imbalances remain nonzero; zero-charge classification is separate. No absolute force cutoff is used to manufacture balance.

19. **Limits and unverified platforms.** The model is classical, planar and nonrelativistic, with ideal abrupt electric-field boundaries, prescribed uniform B and absorbing point-particle plate collisions; it neglects fringing, radiation, induction from live B changes and gravity in Magnetic mode. Some allowed classroom parameter combinations require very high balancing speed or produce curvature far larger than the viewport; neither is artificially shrunk. The numerical speed input's upper bound is a software limit, not a claim of relativistic validity. A 200,000-search defensive guard can reject pathological sequences of physical boundary encounters; reducing time limit is then necessary. The labelled classroom time safeguard remains 30 s by default, adjustable to 3600 s. Validation uses desktop Chromium with emulated touch/viewports. Physical phones, Firefox and Safari/WebKit are unverified. Full-page Chromium screenshots proved unreliable during development; retained checks use actual viewport captures and separately scrolled controls.
